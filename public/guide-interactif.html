⚙️ Laravel (Mario)

C'est le frontend + backend PHP. Il gère :

  • L'affichage des pages (Blade)
  • Les routes HTTP
  • L'authentification des utilisateurs
  • Les appels à l'API Toad
  • Une base SQLite locale pour les films/stocks créés
🐸 API Toad (Java)

C'est le serveur intermédiaire Java Spring Boot. Il :

  • Reçoit les requêtes HTTP de Laravel
  • Accède à la base MySQL Peach
  • Retourne des données JSON
  • Gère le CRUD films & stocks
  • Authentifie via email / mot de passe
🔄 Double source de données — Pourquoi ?
💡L'API Toad est la source principale. Mais si elle est hors ligne, ou si on veut créer des données "privées", on utilise le SQLite local.
📖 LECTURE → API Toad
Les films et stocks sont lus depuis l'API Toad (base Peach distante) en priorité.
✏️ ÉCRITURE → API + fallback SQLite
Création/suppression : tentée via l'API. Si échec → stockage SQLite local.

Les requêtes HTTP

HTTP est le protocole de communication entre le navigateur et le serveur. Il existe 4 méthodes principales (CRUD).

GET Lire

Demander une ressource sans la modifier. Le navigateur envoie un GET à chaque changement d'URL.

// Exemples dans l'application GET /films → liste des films GET /films/42 → détail du film 42 GET /stocks → liste des stocks
POST Créer

Envoyer des données pour créer une ressource. Le formulaire HTML utilise POST.

// Exemples dans l'application POST /films → créer un film POST /login → se connecter POST /stocks/reception→ ajouter DVD
PUT Modifier

Mettre à jour une ressource existante. Les navigateurs ne supportent pas PUT dans les formulaires HTML.

// Exemples dans l'application PUT /films/42 → modifier le film 42 // Laravel utilise un champ caché : <input type="hidden" name="_method" value="PUT">
DELETE Supprimer

Supprimer une ressource. Même contrainte : formulaire HTML + champ _method.

// Exemples dans l'application DELETE /films/42 → supprimer le film 42 // Dans la vue Blade : @method('DELETE') → génère le champ caché
🔄 Cycle complet — Créer un film
1
Navigateur — L'utilisateur remplit le formulaire et clique "Enregistrer".
→ POST /films avec les données du formulaire
2
Routes (web.php) — Laravel reçoit POST /films et appelle FilmController@store.
Route::post('/films', [FilmController::class, 'store'])
3
FilmController::store() — Valide les données (titre, description, année…).
Si invalide → retourne code 422 avec les erreurs
4
ToadFilmService::createFilm() — Appelle POST /films sur l'API Toad.
Si l'API échoue → fallback : création en SQLite local
5
API Toad (Java) — Insère le film dans la base Peach et retourne le film créé en JSON.
Réponse : { "filmId": 1001, "title": "...", ... }
6
Retour Laravel — Redirige vers /films avec message flash "Film créé avec succès".
return redirect()->route('films.index')->with('success', ...)

Section 4 / 7

Authentification

L'app vérifie les identifiants via l'API Toad d'abord, puis en fallback sur la base SQLite locale.

🔄 Stratégie "double source"
1. Formulaire soumis
L'utilisateur envoie email + mot de passe via POST /login.
2. Appel API Toad
ToadAuthService appelle l'API Toad pour vérifier les identifiants. Si succès → token JWT retourné.
3. Fallback local (si l'API est hors ligne)
Laravel cherche l'utilisateur dans la table SQLite et compare le hash du mot de passe avec Hash::check().
4. Stockage en session
Les données utilisateur + token JWT sont sauvegardées : session('toad_user').
5. Connexion Laravel
Auth::login($user) connecte l'utilisateur. Le middleware 'auth' le reconnaîtra sur les requêtes suivantes.
🔑 Le token JWT — À quoi ça sert ?
ℹ️JWT = JSON Web Token. C'est une chaîne de caractères encodée qui prouve que l'utilisateur est authentifié. L'API Toad le retourne après connexion.
// Après login, le token est stocké en session $request->session()->put('toad_user', [ 'token' => 'eyJhbGciOiJIUzI1NiIsInR5cCI6...', // Token JWT 'email' => 'user@example.com', 'name' => 'Jean Dupont', ]); // À chaque appel API suivant, le token est ajouté automatiquement Http::withToken(session('toad_user.token')) ->get('/films'); // → Header: Authorization: Bearer eyJ...
🛡️ La protection CSRF

CSRF = Cross-Site Request Forgery. Une attaque où un site malveillant soumet un formulaire au nom de l'utilisateur. Laravel s'en protège avec un token unique par session.

{{-- Dans chaque formulaire Blade --}} <form method="POST" action="/films"> @csrf {{-- génère : <input type="hidden" name="_token" value="abc123..."> --}} ... </form>
⚠️Si le token CSRF est absent ou invalide → Laravel retourne une erreur 419 Page Expired.

Gestion des films

Le CRUD films combine deux sources : l'API Toad pour la lecture et le SQLite local comme fallback pour l'écriture.

🔀 La fusion locale / distante
// ToadFilmService::getAllFilms() // Étape 1 : Films distants depuis l'API Toad $resp = $this->http()->get($this->baseUrl . '/films'); $remote = array_map([$this, 'normalizeRemote'], $resp->json()); // Indexer les films distants par filmId $indexed = []; foreach ($remote as $f) { $indexed[(string)$f['filmId']] = $f; } // Étape 2 : Films locaux SQLite (remplacent les distants si même filmId) foreach (LocalFilm::all() as $local) { $key = $local->filmId ?? 'local_' . $local->id; $indexed[$key] = $norm; // override ! }
💡Un film local avec filmId = 100 va écraser le film distant avec filmId = 100 dans la liste. Cela permet de modifier un film Peach sans accès direct à la base.
🆔 Film local vs Film distant
✅ Film distant (API Peach)
{ "filmId": 42, "title": "ACADEMY DINOSAUR", "source": "remote" }
filmId = entier numérique
Vient de la base Peach
🏠 Film local (SQLite)
{ "filmId": "local_7", "title": "Mon nouveau film", "source": "local" }
filmId = "local_" + id SQLite
Créé localement
🗑️ Suppression — logique conditionnelle
public function deleteFilm($id): bool { if (str_starts_with($idStr, 'local_')) { // Film purement local → supprimer directement en SQLite $local->delete(); return true; } // Film distant → appel DELETE /films/{id} sur l'API Toad $resp = $this->http()->delete($this->baseUrl . '/films/' . $id); // Supprimer aussi l'override local si existant $local?->delete(); }

Gestion des stocks

Chaque film peut avoir plusieurs exemplaires physiques (DVD). Le stock est géré via l'API Toad (inventaire Peach).

📊 Les 3 compteurs
N
Total
Tous les exemplaires du DVD
N
Disponibles
Non loués, présents en magasin
N
Occupés
Loués ou en panier client
➕ Ajouter des DVD — POST /stocks/reception
// StockController::reception() $request->validate([ 'filmId' => 'required', 'quantite' => 'required|integer|min:1', 'storeId' => 'required|integer|min:1', ]); // Le service crée N entrées dans la table inventory (une par DVD physique) $this->inventoryService->addStock( $request->filmId, $request->quantite, $request->storeId );
➖ Retirer des DVD — POST /stocks/retrait

On ne peut retirer que des exemplaires disponibles (non loués). Un motif est obligatoire pour la traçabilité.

// Les motifs acceptés 'casse' → DVD endommagé physiquement 'perte' → DVD perdu 'vol' → DVD volé 'obsolete' → retiré de la vente 'autre' → autre raison
